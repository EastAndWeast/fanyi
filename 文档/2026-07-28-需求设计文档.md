# 需求设计文档 — 上传前配置翻译 API

## 原始需求描述

用户希望在上传视频之前配置翻译 API Key，避免视频处理完成后才发现没有中文字幕。

## 问题重定框

用户需要的不是单独增加一个输入框，而是在启动耗时的视频处理前，明确知道中文翻译是否已启用，并能提前完成配置。

## 用户反馈

- 当前问题：视频生成完成后才发现没有中文。
- 使用频率：经常处理需要中文字幕的视频。
- 用户规模：很多人会使用。
- 成功标准：上传前可配置并保存；未配置时明确提醒；配置后自动生成中文。
- 最小范围：复用现有 API 配置表单。
- 存储约束：API Key 仅保存在当前浏览器，不进行云端同步。

## 关键假设与挑战

- 假设用户会在编辑页主动寻找 API 设置。实际上传后会立即进入自动处理，发现配置缺失时已经太晚。
- 假设一条文字提示足够。实际提示没有提供直接操作入口，用户仍然无法在当前页面解决问题。
- 假设所有用户都需要中文。实际应允许未配置用户继续生成英文字幕，但必须明确说明结果。

## 三种实现路径

| 路径 | 核心思路 | 时间估算 | 主要风险 |
|------|---------|---------|---------|
| 最小路径 | 上传页复用现有配置表单，显示已配置/未配置状态 | 数小时 | 页面纵向空间增加 |
| 标准路径 | 增加配置校验、连接测试和上传前确认 | 1–2 天 | 需要处理不同供应商错误格式 |
| 完整路径 | 账号系统、服务端加密存储、多设备同步 | 1–2 周 | 密钥安全和账户体系复杂度高 |

## 推荐方案

采用最小路径：

- 在上传区域上方增加可展开的“翻译 API 配置”卡片。
- 未配置时默认展开，并明确说明只会生成英文字幕。
- 已配置时显示服务商和模型，可随时修改。
- 继续使用现有 `localStorage` 持久化，不新增服务端密钥存储。

## 验收标准

- 上传页可输入 Provider、API Key、Endpoint 和模型。
- 刷新页面后配置状态仍然保留。
- 未配置时显示明确警告，但允许只生成英文字幕。
- 配置后上传视频，处理阶段自动执行中文翻译。
